## 1. Payment not working — BLOCKER

### Root cause (confirmed, not a code bug)

`PaymentLogs` on production shows **every** order-create call failing:

```
order.create_failed | Razorpay order creation failed (401): {"error":{"description":"Authentication failed"}}
```

Most recent: a burst of 9 failures on 2026-09-04 17:46 (payment IDs 16–24).

The running API does not have a valid Razorpay **KeySecret**. In Production, user-secrets are not
loaded and `appsettings.Production.json` ships the Razorpay keys blank on purpose — they must come
from environment variables on the host, and `Razorpay__KeySecret` there is missing or wrong.

Verified against Razorpay's live API (read-only `GET /v1/payments` probe):

- `rzp_live_S3Q4YDApitfjh3` + `h3KFlVIJyYj5r1jm6X4TPp6G` → **HTTP 200** (valid)
- same key + `hKFlVIJyYj5r1jm6X4TPp6G` (truncated, missing the `3`) → **HTTP 401**

The frontend and backend payment code paths (`create-order → checkout → verify`, webhook,
reconciliation) are all sound.

### What shipped

- **`GET /api/admin/payments/razorpay-health`** — read-only auth probe + masked config report. No
  money moves. Surfaced as a banner at the top of **Admin → Payments**: green "Connected" or red
  "NOT working" with the exact fix. Lets you confirm a deploy without taking a real payment.
  (Verified: local reports `authenticated: true`.)
- Startup now logs **CRITICAL** (not a quiet warning) when `Razorpay:KeySecret` is blank in Production.
- `deploy/systemd/jobcharcha-api.service` + `deploy/jobcharcha-api.env.example` + `deploy/RAZORPAY-CONFIG-FIX.md`
  — real config templates (the API systemd unit wasn't in the repo before) with the working values and commands.
- `BackgroundSweeps:Enabled` config flag — the two hourly sweeps (live Razorpay resync, real
  expiry emails) are now **off in Development** so a local run against prod data can't fire them.

### You still need to do

## 2. CBT mock-test delete not working — MAJOR

### Root cause

- Backend `TestService.DeleteAsync` **hard-blocked** any test with ≥1 attempt
  (`"Cannot delete a test that already has attempts. Deactivate it instead."`). Every real test
  that's ever been attempted could never be deleted.
- Frontend `AdminMockTestsPanel.handleDelete` had **no try/catch** — the 400 response was swallowed,
  no error shown, list never refreshed. From the admin's side: "nothing happens".

### What shipped (soft-delete / archive — your chosen behavior)

- New `Tests.IsDeleted` column (migration `AddTestSoftDelete`). `DeleteAsync` now sets
  `IsDeleted = true`, `IsActive = false` — **always succeeds**, idempotent, keeps the row, its
  questions/sections, and every attempt + purchase.
- Archived tests are filtered out of the public catalogue, `GET /api/tests/{slug}`, the admin list,
  and exam test-counts.
- Frontend: button relabelled **Archive**, two-step confirm with an explainer ("hidden from
  students and this list… attempts stay in the database"), try/catch with a visible error, and
  optimistic row removal + reload.

### Verified

Archived the seeded bilingual test **which had a real attempt** → succeeded; row kept with
`IsActive=0, IsDeleted=1`; 1 attempt + 6 questions preserved; gone from `/api/tests` (`[]`) and
`/api/tests/{slug}` → 404; admin row vanished immediately.

### You still need to do

Apply the migration to production: `deploy/2026-09-09_AddTestSoftDelete.sql` (idempotent,
transactional, single additive `ALTER TABLE Tests ADD IsDeleted bit NOT NULL DEFAULT 0`), or
`dotnet ef database update` from a machine pointed at prod. Until then, test queries 500 with
`Invalid column name 'IsDeleted'`.

## 4. Mock-test UI/UX redesign + Gujarati + mobile — MAJOR (UX)

### New test-taking layout (`MockTestPage.tsx`, fully rewritten; attempt/timer/save/submit logic unchanged)

- **Sticky compact header**: title · in-test **EN / ગુજરાતી** toggle · prominent **timer pill**
  (emerald → amber under 5 min → pulsing red under 1 min) · Submit button. Full-width **progress
  bar** (answered / total) under it.
- **Question panel**: section chip, "Q n / total", large question text, options as full-width
  touch targets (≥52 px) with A/B/C/D letter badges and a check state.
- **Desktop (≥1024px)**: persistent right **question palette** sidebar with its own language
  toggle and a live legend (Answered / Not answered / Marked / Not visited counts).
- **Mobile / tablet**: sticky bottom action bar (Prev · "n/total answered · Palette" · Next/Review)
  + a **palette bottom sheet** (grid + legend + language toggle + Submit). No horizontal scroll;
  safe-area padding for notched phones.
- Desktop keyboard shortcuts: `1–4` / `A–D` select, `←` `→` change question.
- Instructions, review-summary, and scorecard screens redesigned to match and made responsive.

### Gujarati support

- `Noto Sans Gujarati` added to the font load; new `.lang-gu` CSS utility (line-height 1.9,
  word-spacing) applied to every Gujarati text container so matras don't clip or overlap.
- Backend now exposes Gujarati fields through the attempt API: `AttemptQuestionDto` /
  `AttemptResultQuestionDto` gain `QuestionTextGu` + `OptionA–D Gu` (+ `ExplanationGu`),
  `AttemptSessionDto` gains `TestTitleGu` and `HasGujarati` (drives the toggle's visibility),
  `TestDetailDto` gains `TitleGu` / `InstructionsGu`. Falls back to English per-field where a
  translation is missing, so a partly-translated test still reads cleanly.
- The in-test language choice persists (`localStorage`), independent of the site's EN/HI nav switch.

### Verified (browser, local QA DB, bilingual seeded test)

Instructions → toggle EN⇄ગુજરાતી (title + instructions) → Start → question + all 4 options render
in Gujarati with correct spacing → answer → palette + progress update → toggle to EN mid-test →
review summary → submit → scorecard → answer review with A./B./C./D. prefixes. Desktop layout
confirmed live; mobile layout (bottom bar + palette sheet) confirmed via forced-breakpoint emulation
(the test browser window would not resize below ~1400px).
